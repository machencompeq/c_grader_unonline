# 比對演算法完整機制 (comparator.c)

這份文件把「學生輸出 vs 標準答案 → 差異數 (CHAR)」的每一步講清楚：做了什麼、為什麼、邊界情況怎麼算。
程式碼在 [src/comparator.c](../src/comparator.c)，報告的紅綠標示在 [src/report.c](../src/report.c) 的 `mark_differences`。

## 0. 一句話

**差異數 = 兩段文字經過「完全相同的整理」之後的 Levenshtein 編輯距離**：
把學生輸出改成標準答案，最少需要幾次「新增一個字 / 刪除一個字 / 把一個字換成另一個字」。
中文字算 1 個字；長輸出用帶狀演算法保證仍是精確值，只有極端情況才退回近似值並標記。

## 1. 整體流程

```
標準答案 bytes ──┐                                    ┌── 學生輸出 bytes
                 ▼                                    ▼
 ① 解碼 UTF-8 → Unicode 字元陣列 (去 BOM、\r\n→\n、壞 byte 各算 1 字)
                 ▼                                    ▼
 ② 折疊 (選項)：全形→半形、大寫→小寫
                 ▼                                    ▼
 ③ 逐行過濾 (選項)：去行尾空白、刪空白行、刪含關鍵字的行；最後去掉整段結尾空白
                 ▼                                    ▼
 ④ 比對模式：Strict 不動 / Ignore Whitespace 刪所有空白 / Token 連續空白合併成一個
                 └──────────────┬─────────────────────┘
                                ▼
 ⑤ 去掉相同的開頭與結尾 (不影響距離，但省掉大部分計算)
                                ▼
 ⑥ 很短 (≤ 4096 格) → 教科書動態規劃
    其他 → Myers 位元平行演算法 (精確，一次算 64 格；pattern ≤ 200 萬字、n×⌈m/64⌉ ≤ 20 億)
    Myers 不適用 → 完整動態規劃 (≤ 5000 萬格) → 帶狀演算法 (帶寬 64、128、256… 加倍)
    全部超過預算 → 近似值 (逐位置比較 + 長度差)，approximate = 1
                                ▼
 ⑦ scorer：差異數 → 扣分 (差異 0 一律不扣)
```

兩邊走的是同一個 `normalize()`，所以任何寬容規則對標準答案與學生都一致；不會出現「標準答案有尾隨空白被算成學生的錯」這種不對稱。

## 2. 步驟 ①：解碼

`compare_decode_utf8()`，輸入 bytes，輸出 `uint32_t` 陣列 (每格一個 Unicode 碼位)。

| 規則 | 說明 | 例子 |
|---|---|---|
| 去 BOM | 開頭 `EF BB BF` 略過 (Windows 記事本存的 UTF-8 常有) | `﻿abc` = `abc` |
| `\r\n` → `\n` | Windows 換行視為 `\n`；**單獨的 `\r`** 保留為一個字元 | `a\r\nb` = `a\nb`；`a\rb` ≠ `a\nb` |
| 中文 = 1 字 | 3 個 byte 的 `系` 解成 1 格 | `系所` 長度 2 |
| 壞 byte | 不合法的 UTF-8 byte 各自變成一個私有碼位 `0xDC00 + byte` | 學生印出 Big5 亂碼 `\xA4\xA4` → 2 個字，各算差異 |
| 4-byte 字 | Emoji 等 U+10000 以上一樣算 1 字 | 🎉 長度 1 |

為什麼壞 byte 要「各算一字」而不是丟掉：學生程式用 Big5 印中文、或陣列溢位印出垃圾時，這些內容確實是錯的輸出，
必須被算進差異；同時任何 byte 序列都能解碼，比對永遠不會因為編碼錯而崩潰。報告顯示時再把這些字換成 �。

## 3. 步驟 ②：折疊 (選項)

`fold_char()`，逐字處理，只在選項開啟時做：

- **全形視為半形** (`fullwidth_as_halfwidth`)：U+FF01～U+FF5E 減去 0xFEE0 變成 ASCII `!`～`~` (涵蓋全形英數與標點：`：`→`:`、`１`→`1`、`Ａ`→`A`)；全形空白 U+3000 → 半形空白。
  **不會**轉換的：`￥`、`｡`、`「」` 等不在這個區間的符號。
- **忽略大小寫** (`ignore_case`)：只把 ASCII `A`～`Z` 變小寫；中文與其他文字不受影響。

「忽略含關鍵字的行」的關鍵字本身也會做同樣的折疊，所以老師打半形 `:` 也能匹配學生的全形 `：`。

## 4. 步驟 ③：逐行過濾 (選項)

`filter_lines()`，以 `\n` 切行，逐行決定要不要留、留多少：

1. **去行尾空白** (`ignore_trailing_space`)：行尾的空白、Tab、全形空白、不斷行空白 (U+00A0)、`\v`、`\f` 全部去掉。
   行首與行中的空白照算 (`a b` vs `a  b` = 1)。
2. **刪空白行** (`ignore_blank_lines`)：整行只有空白 (同上定義) 就整行連換行一起拿掉。
3. **刪含關鍵字的行** (`ignore_lines_with`)：老師填 `請輸入|請依序`，以 `|` 分成最多 16 個關鍵字，前後空白去掉；
   一行只要**包含** (子字串) 任一關鍵字，整行連換行拿掉。用途：學生的提示文字寫法各異 (`請輸入姓名:` / `請輸入你的姓名：`) 不扣分。
4. 最後若開了「去行尾空白」，**整段輸出結尾**的所有空白與換行也去掉 → 少印或多印最後一個 `\n` 不算差異。

保留的行之間仍以 `\n` 分隔，所以行的結構還在；只有下一步的模式才會改變空白的意義。

## 5. 步驟 ④：比對模式

`apply_mode()`：

| 模式 | 做法 | `Hello World` vs `Hello  World` | `Hello World` vs `HelloWorld` | `1 2\n3` vs `1 2 3` |
|---|---|---|---|---|
| Strict | 不動 | 1 | 1 | 1 |
| Ignore Whitespace | 刪掉所有空白 (含換行、Tab、全形空白) | 0 | 0 | 0 |
| Token | 連續空白 (含換行) 合併成一個半形空白，去掉開頭與結尾的空白 | 0 | 1 | 0 |

Token 模式的意思是「只看資料的順序與內容，不看排版」：`HelloWorld` 少了分隔，token 數不同，所以仍算 1 個差異。

## 6. 步驟 ⑤～⑥：編輯距離

### 6.1 定義

Levenshtein 距離 `D(a, b)`：把 `a` 變成 `b` 的最少操作數，操作只有三種、成本都是 1：
插入一個字、刪除一個字、替換一個字。它是對稱的 (`D(a,b) = D(b,a)`)。

例子 (Strict)：

| 標準答案 | 學生輸出 | 差異數 | 說明 |
|---|---|---|---|
| `ABCDEFG` | `ABCDEFG` | 0 | |
| `ABCDEFG` | `ABCXEFG` | 1 | 替換 D→X |
| `ABCDEFG` | `ABCXYFG` | 2 | 替換兩個 |
| `ABCDEFG` | `ABC` | 4 | 少了 DEFG |
| `ABCDEFG` | `ABXCDEFG` | 1 | 多插一個 X **只算 1**，後面不會整排錯位 |
| `printf` | `pirntf` | 2 | 相鄰對調 = 刪 + 插 (或兩次替換)，沒有「對調算 1」的規則 |
| `Sum: 150` | `Sum: 15` | 1 | |
| `系所: 資工` | `系所: 資管` | 1 | 中文字 1 個 |

### 6.2 遞迴式與完整動態規劃

令 `a` 長 n、`b` 長 m，`D[i][j]` = `a` 前 i 個字變成 `b` 前 j 個字的距離：

```
D[0][j] = j            (全部插入)
D[i][0] = i            (全部刪除)
D[i][j] = min( D[i-1][j] + 1,                 刪 a[i]
               D[i][j-1] + 1,                 插 b[j]
               D[i-1][j-1] + (a[i] != b[j]) ) 替換 (相同就免費)
```

`full_distance()` 只保留「上一列」與「目前這列」兩列 (O(min(n,m)) 記憶體)，時間 O(n×m)。
先讓較短的當 `b`，記憶體更省。上限 5000 萬格 (例如 7000×7000)，約 0.1～0.3 秒。

### 6.3 先去掉相同的開頭與結尾

編輯距離不受共同前綴 / 後綴影響 (最佳路徑一定沿對角線走過它們)，所以先把兩邊相同的開頭與結尾去掉，
只對中間不同的部分算。學生輸出通常只有一小段不同，這一步讓大部分比對變成幾百格。

### 6.4 Myers 位元平行演算法 — 主要方法

`myers_distance()`，Myers (1999) 的 O(⌈m/64⌉ × n) 演算法，Hyyrö 的多字組 (block) 版本 (公式與 edlib 相同)。
想法：動態規劃表相鄰兩格的差只會是 −1、0、+1，所以每一直行可以用兩個位元向量表示
(`Pv` = 往下 +1 的位置、`Mv` = 往下 −1 的位置)；對 text 的每個字元，用「該字元出現在 pattern 哪些列」
的位元遮罩 `Eq` 做幾個 AND / OR / 加法 / 移位，就一次更新 64 列。

- pattern 取較短的一邊，切成 64 列一組；字組之間傳遞水平差分 (hin / hout)，第 0 列的水平差分固定 +1。
- 字元 → 遮罩用開放定址雜湊表 (中文也可以)；遮罩表記憶體 = 相異字元數 × 字組數 × 8 bytes，上限 128 MB。
- 結果與教科書動態規劃**完全相同** (測試用 600 組隨機英文/中文字串與 5000×5000 的例子逐一核對)，
  速度快 30～60 倍：12 萬 × 12 萬 (144 億格) 完全不同的兩段文字約 0.5 秒就有精確值。
- pattern 超過 200 萬字、或 n × 字組數超過 20 億時不用，改走下面的方法。

### 6.5 帶狀演算法 (Ukkonen) — 備援

當中間部分 n×m 超過 5000 萬格 (例如兩邊各 8,000 字、差異散在前後)，`banded_distance()`：

- 只計算 `|i − j| ≤ band` 的格子 (對角線附近一條帶)，其他格視為無限大。
- **正確性**：任何成本 ≤ band 的編輯路徑，走到任何一格時 `|i − j|` 都不會超過 band (每偏離對角線一格至少要一次插入或刪除)，
  所以若真正距離 ≤ band，帶內算出的就是精確值；若帶內算出的值 > band，只能確定真正距離 > band。
- **加倍搜尋**：band = 64 → 128 → 256 → …，第一次得到 ≤ band 的結果就回傳。總成本 ≈ n × 4 × 最終帶寬。
  兩邊各 100 萬字、差異 100 處：約 100 萬 × 4 × 128 ≈ 5 億格以內；差異 10 處只要 64 的帶就結束。
- 記憶體：每列只存帶內 `2×band+1` 格，兩列。

### 6.6 近似值 (最後手段)

Myers、完整動態規劃、帶狀搜尋都超出預算 (兩邊各數百萬字且差異極多) 才退回：
`差異 ≈ 同位置不同的字數 + 長度差`，並把 `approximate` 設成 1。畫面、報告、CSV 都會標「(近似)」。
這種情況學生分數早已是 0 或接近 0 (區間表 21+ 就扣光)，近似值不影響公平。

### 6.7 記憶體不足

`malloc` 失敗時同樣退回近似值並標記，不會當掉。

## 7. 差異數以外的兩個功能

### 7.1 第一個不同處 (畫面提示)

`compare_first_difference()` 對**未經選項處理**的原始文字逐字比對，回報第 N 行第 M 個字 (從 1 開始，以字元計)。
只是給老師快速定位；因為沒套用比對選項，它可能指到一個「不扣分」的位置。

### 7.2 報告的差異標示 (report.c，diff-match-patch 風格)

1. **差異腳本**：用完整的 (n+1)×(m+1) 表格 (上限 800 萬格，超過就只算差異數不標示) 算同樣的編輯距離，
   **從右下角回溯**得到一串「相同 / 學生少了 (刪除) / 學生多了 (插入)」的段落；替換 = 刪除 + 插入。
2. **合併整理** (同 diff-match-patch 的 `cleanupMerge`)：相鄰同類段落合併，「刪插刪插…」交錯改成「一段刪除 + 一段插入」。
3. **語意清理** (同 `cleanupSemantic`)：夾在兩段修改之間、又比前後修改都短的「相同」小碎片 (≤ 12 字) 併進修改裡。
   例如 `Average` vs `Avg`：原本是「Av + 刪 era + g + 刪 e」，清理後變成「Av + 刪 erage + 插 g」，一眼看出是整個字寫錯，
   而不是散落的單字。
4. **兩種呈現**都來自同一份腳本：
   - **合併檢視**：一份文字，紅色刪除線 = 標準答案有但學生少了，綠底 = 學生多出來的 (diff-match-patch 的 `prettyHtml`)。
   - **左右對照**：標準答案 / 學生輸出各自標示 (舊格式，方便逐行對照)。
- 標示的是**逐字**差異、不套用比對選項 (老師要看得到學生實際印了什麼)，所以「有標示但不扣分」是正常的，報告會註明。
- 空白顯示為 `·`、Tab 為 `→`、換行為 `↵`；跨行的刪除或插入會在每一行分別標示，保持行的結構。
- 同一套流程也用在「編譯錯誤的 AI 自動修正」：原始碼紅字 = 被 AI 改掉或刪除，修正後綠字 = AI 新增或改成。

## 8. 差異數怎麼變成分數 (scorer.c)

- 每題滿分 = 滿分 ÷ 測資數；每題各自算：`得分 = max(0, 題滿分 − penalty(差異數))`。
- `penalty`：每 CHAR (`diff × X`)、每 N CHAR (`⌊diff / N⌋ × X`)、區間 (查表，`ALL` = 扣光)。
- **差異數 0 永遠 penalty 0**，即使區間表沒有 0～0 這條 (以前會被扣光，已修正)。
- TLE / OLE 沒有差異數 (顯示 `-`)，該題 0 分；RE 預設仍比對已印出的部分。
- AI 修正過的學生另外有「修正字元數」= `compare_outputs(原始碼, 修正後, Strict + 忽略行尾空白)`，
  修正扣分 = min(修正字元數 × 每 CHAR 扣分, 上限)，最後 `成績 = max(0, 各題得分總和 − 修正扣分)`。

## 9. 常見疑問

| 問題 | 答案 |
|---|---|
| 學生多印一個換行會扣分嗎？ | 開「忽略行尾空白與結尾換行」就不會 (建議模板預設開)；Strict 且沒開則算 1。 |
| 學生把 `Average: 30.00` 印成 `Average:30.00`？ | Strict 差 1 (少一個空白)；Ignore Whitespace 差 0；Token 差 1 (token 數不同)。 |
| 學生用全形冒號？ | 開「全形半形視為相同」差 0，否則差 1。 |
| 學生的提示文字跟老師不一樣？ | 用「忽略含以下文字的行」填提示文字的關鍵字；或用「只看資料」模板。 |
| 輸出順序對、但多印了一行除錯訊息？ | 那一行的每個字 + 換行都算差異 (例如 `debug=3\n` = 8)；區間表通常落在 6～10 → 扣 5。 |
| 中文亂碼 (Big5 程式)？ | 每個壞 byte 算 1 字差異；原始碼是 Big5 的話工具會先轉成 UTF-8 再編譯，正常情況不會亂碼。 |
| 兩份輸出都很長 (幾萬字)？ | 帶狀演算法仍給精確值；只有差異也非常大時才近似並標示。 |
| 差異數對稱嗎？ | 是，`D(標準, 學生) = D(學生, 標準)`。 |

## 10. 已知限制

1. 全形折疊只涵蓋 U+FF01～U+FF5E 與全形空白；其他全形符號不轉。
2. 「忽略大小寫」只影響英文字母。
3. 關鍵字是子字串比對，老師填太短的關鍵字 (例如 `:`) 會把很多行都忽略掉。
4. 報告標示的上限是 800 萬格 (約 2800×2800 字)，超過只有差異數沒有標示。
5. 近似值路徑 (數百萬字且極端不同) 的差異數不是精確值，但一定有 `(近似)` 標記。

## 11. 測試

`tests/test_core.c` 涵蓋：規格書的例子、中文、BOM/CRLF、三種模式、每個選項、關鍵字行、壞 byte、
9,000 字兩端有差異 (= 3)、開頭多一字 (= 2 而不是幾千)、12 萬字完全不同 (Myers 精確 = 120000)、
600 組隨機英文/中文字串 + 5000×5000 與教科書動態規劃逐一核對、第一個不同處。

## 12. 為什麼不用現成函式庫

用的都是標準演算法 (Levenshtein / Myers 1999 / Ukkonen 1985 / diff-match-patch 的清理規則)，只是自己用 C 實作：
專案原則是純 C、零相依、老師雙擊就能跑，而且需要自訂的前處理 (Unicode 字元、全形折疊、關鍵字行、Token 模式) 與回溯標示，
現成函式庫 (RapidFuzz、python-Levenshtein、diff-match-patch 的 C 移植) 通常只給距離或片段、又要另外編譯連結。
