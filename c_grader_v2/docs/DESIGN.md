# 程式架構

本機 TA 批改工具，純 C 撰寫 (Win32 API)，不需要安裝其他函式庫。**不是** Online Judge，也不是安全沙盒。
圖形化的模組圖、流程圖見 [ARCHITECTURE.md](ARCHITECTURE.md)；審查結果見 [REVIEW-2026-09-23.md](REVIEW-2026-09-23.md)。

## 1. 分層

```
┌──────────────────────────── 介面層 (只負責畫面與輸入，不含批改邏輯) ───────────────────────────┐
│ main.c + gui.c         主視窗：資料夾、模板、比對選項、評分方式、CE 自動修正、結果表格、背景執行緒 │
│ gui_rules.c            「編輯評分規則」視窗 (區間表 + 即時檢查)                                   │
│ gui_detail.c           學生詳細視窗 (各題 Expected / Actual、AI 修正)                             │
│ gui_tests.c            「編輯測資」總表視窗 (整批編輯、AI 產生、預覽參考答案輸出)                 │
│ gui_common.c           字型、DPI 縮放、模態視窗、文字視窗、工具提示、深色科技風主題 (自繪按鈕/表頭) │
│ cli_main.c             命令列版 (與 GUI 共用下面所有模組)                                         │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
                 │ 只呼叫 grader_* / config_* / score_validate / report_* / export_csv
┌──────────────────────────────────── 流程層 ──────────────────────────────────────────────────┐

│ report.c    老師版 (含隱藏測資、全班總表) / 學生版 (隱藏測資只顯示結果) HTML 報告               │

└──────────────────────────────────────────────────────────────────────────────────────────────┘

│ scorer.c      差異數 → 扣分；檢查區間規則 (重疊/空缺/最小>最大)                                 │
│ config.c      設定預設值、grader.cfg 讀寫、評分模板、修正扣分                                   │
│ ai_fix.c      找本機 AI CLI (claude/codex/gemini/自訂)、把提示詞送 stdin 取回 stdout、取出程式碼 │
│ roster.c      名單.csv：資料夾名稱 (拼音) → 中文姓名、學號                                       │

└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 2. 一次批改的資料流

```
grader.cfg ─► GradeConfig ─────────────────────────────────────────────┐
                                                                      ▼
參考答案 hw1.c (測資在 hw1_測資\) ─► 編譯 ─► 對每個 .in 執行 ─► 標準答案 (有 .out 就用 .out 並檢查一致)
                                                                      │
學生資料夾 ─► 每個子資料夾 (學號)                                        │
      找 .c (含子資料夾) ─► 非 UTF-8 逐行轉成 UTF-8 副本 ─► 編譯 (多檔失敗改單檔)   │
         │ 失敗 → ai_fix 開啟且單一 .c：原始碼 + gcc 訊息 → 本機 AI → 修正後再編譯   │
         │        修得好 → 修正字元數 = 編輯距離(原始碼, 修正後)；修不好 → CE，0 分   │
         ▼                                                            ▼
      對每個 .in 執行 (60 秒 / 10MB / 512MB) ─► 學生輸出 ─► comparator ─► 差異數 ─► scorer ─► 題分
                                                                      │
      成績 = max(0, 各題得分總和 − 修正扣分)                            │
StudentResult[] ─► 畫面表格、學生詳細、reports\*.html、result.csv ◄────┘
```

暫存 (.exe、輸出檔、AI 的提示詞與回答) 放在 `%TEMP%\c-grader\run-*`，批改完刪除 (`keep_temp = 1` 保留)；學生資料夾全程唯讀。

## 3. 差異數 (comparator.c)

完整說明 (含例子與演算法論證) 見 [COMPARATOR.md](COMPARATOR.md)。

1. 讀檔 → 去 UTF-8 BOM → `\r\n` 視為 `\n` → 以 **Unicode 字元**為單位 (中文字 = 1 CHAR；不合法的 byte 各算 1 CHAR)
2. 比對選項：全形轉半形、忽略大小寫 → 逐行：去行尾空白 (含 Tab、全形空白)、刪空白行、刪含關鍵字的行
3. 比對模式：Strict 不動／Ignore Whitespace 刪所有空白／Token 連續空白合併為一個
4. **Levenshtein 編輯距離**：最少幾次「新增／刪除／替換一個字」
   - `ABCDEFG` vs `ABCXEFG` = 1、`ABCXYFG` = 2、`ABC` = 4；多印一個字只算 1，不會讓後面整排錯位
   - 先去掉相同的開頭與結尾；剩餘 ≤ 5000 萬格用完整動態規劃；更長改用帶狀 (Ukkonen) 演算法
     (帶寬 64、128、256… 加倍，距離 ≤ 帶寬就是精確值)；工作量超過 4 億格才退回近似值並標記
5. 標準答案與學生輸出經過**完全相同**的處理，所以規則對每個人一致

報告中的紅/綠標示用同一個編輯距離的回溯路徑算出 (上限 300 萬格)。

## 4. 評分 (scorer.c、config.c)

- 題滿分 = 滿分 / testcase 數；題分 = max(0, 題滿分 − penalty(差異數))；總分 = 各題相加
- 每 CHAR：`diff × X`；每 N CHAR：`floor(diff / N) × X`；區間：查表 (max 可為 MAX，扣分可為 ALL)
- **差異數 0 一律不扣分**，即使區間表沒有 0～0 的規則
- 規則檢查：重疊、最小 > 最大、負數、沒有規則 → 不能批改；空缺 (從 1 開始算) → 提醒 (空缺內扣光)
- TLE / OLE → 該題 0 分；RE → 預設仍比對當掉前的輸出 (可設定直接 0 分)
- RE 判斷：結束碼是 Windows 當機碼 (0xC0000005 等)；`return 1` 不算 RE
- **CE 自動修正** (`ai_fix = 1`)：修正扣分 = min(修正字元數 × `ai_fix_penalty_per_char`, `ai_fix_penalty_max`)；
  成績 = max(0, 各題得分總和 − 修正扣分)。找不到工具、超時、修 `ai_fix_attempts` 次仍失敗 → 維持 CE 0 分

## 5. 執行學生程式的安全措施 (executor.c)

| 措施 | 做法 |
|---|---|
| Timeout | 預設 60 秒，超過 `TerminateJobObject`；時間限制 < 10 秒時第一次超時會重跑確認 |
| 輸出上限 | 輸出直接寫檔，每 20ms 檢查大小，超過 10MB 結束 (超大輸出只讀前 64 KB 給畫面) |
| 記憶體上限 | Job Object 每個 process 512MB |
| 強制結束 | Job Object `KILL_ON_JOB_CLOSE`：學生程式開的子程式也一起結束 |
| 當掉不跳視窗 | `SetErrorMode` + `DIE_ON_UNHANDLED_EXCEPTION` |
| stdin | 只接 testcase 檔，讀完就 EOF，不會等鍵盤 |
| AI 工具 | 同一套 `run_program`：`ai_fix_timeout_ms` (預設 180 秒)、回答上限 4 MB |

這些只防「寫錯的程式」，**不防惡意程式**。要公開在網路上讓人提交，需要真正的沙盒 (VM / 容器 / 低權限帳號)。

## 6. 測試

`mingw32-make test` 執行 `tests/test_core.c` (814 項)：規格書的差異數例子、中文、換行、三種比對模式、
所有比對選項、長輸出的帶狀精確與近似退回、三種評分模式的扣分、差異 0 不扣分、規則檢查、設定檔讀寫 (含值裡的 `#`)、
每個模板、模板反查、名單學號推測、測資總表匯入匯出、AI 回答的程式碼擷取與提示詞、透過 cmd 走一趟 AI 呼叫、CSV 引號與公式防護、限制長度讀檔。

`tests\fixtures\Homework\students` 的範例學生涵蓋：正確、打錯字、多空白、編譯錯誤、無窮迴圈、無限輸出、當掉、
少最後換行、空資料夾、Big5 原始碼、兩個 .c、放在子資料夾、編碼混雜、散裝 .c、印完才當掉。
用 `build\grader_cli.exe tests\fixtures\Homework --no-report --detail` 可以整批跑一次；
把 `grader.cfg` 的 `ai_fix_tool` 指到一個會印出修好程式的命令 (例如 `cmd /c type 修好的.c`) 就能離線測 CE 修正流程。

## 7. 工具腳本 (tools\)

| 腳本 | 用途 |
|---|---|
| ai_testcases.ps1 | 找本機 claude → codex → gemini，把參考答案交給 AI 產生測資輸入 (總表格式) |
| ai_roster.ps1 | 貼上教學平台名單 → 英文名直接比對、中文名交給 AI 依拼音配對 → 更新 名單.csv |

兩者都用 `cmd` 重新導向傳遞 UTF-8 位元組 (避開 PowerShell 5 的編碼轉換)，
AI 的輸出只當作「候選」：測資的標準答案一律由參考答案執行產生；名單配對只接受實際存在的資料夾與名單上的名字。
`src\ai_fix.c` 用同一個工具命令表 (`claude -p --output-format text` 等)，工具版本參數不同時三處一起改，或在設定檔用 `ai_fix_tool = 自訂命令列`。
