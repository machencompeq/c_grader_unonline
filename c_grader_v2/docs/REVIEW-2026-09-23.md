## 1. 文字比對目前的方法 (comparator.c)

| 步驟 | 做法 | 備註 (容易誤解的細節) |
|---|---|---|
| 解碼 | UTF-8 → Unicode 字元陣列；去 BOM；`\r\n` → `\n` | 單獨的 `\r` 保留為一個字；**不合法的 byte 各算 1 CHAR** (學生印出亂碼時每個 byte 都算差異)；中文字 = 1 CHAR |
| 折疊 (選項) | 全形→半形：只有 U+FF01～U+FF5E 與全形空白 U+3000；忽略大小寫：只有 A–Z | 其他全形符號 (例如 ￥、｡) 不會轉；非英文字母的大小寫不處理 |
| 逐行 (選項) | 去行尾空白 (現在含 Tab、全形空白、不斷行空白)、刪空白行、刪含關鍵字的行 | 關鍵字最多 16 個、以 `\|` 分隔、前後空白去掉、關鍵字也做同樣折疊；「含」= 子字串比對，整行 (含換行) 拿掉。「去行尾空白」同時也把整個輸出結尾的空白/換行全部去掉，所以少最後一個換行不扣分 |
| 模式 | Strict 不動；Ignore Whitespace 刪掉所有空白 (含換行)；Token 連續空白合併成一個、去頭尾 | Token 下 `Hello World` vs `HelloWorld` = 1 (token 數不同) |
| 距離 | 先去相同開頭/結尾；Levenshtein (新增/刪除/替換各 1)；相鄰兩字對調 = 2 | 標準答案與學生輸出走**完全相同**的處理，規則對每個人一致 |
| 太長時 | (修正前) n×m > 5000 萬格改用「逐位置比較」；(修正後) 帶狀精確演算法，工作量超過 4 億格才近似 | 詳見第 3 節第 2 項 |

報告中的紅/綠標示用另一份 n×m 完整表格回溯 (上限 300 萬格)，並且標示的是**逐字**差異、不套用比對選項，所以「有標示但不扣分」是正常的。

## 2. 測資造成 overflow / 輸出異常時的處理

| 情況 | 現在的處理 |
|---|---|
| 陣列/緩衝區溢位導致**當掉** (0xC0000005 存取違規、0xC00000FD 堆疊溢位等 NTSTATUS 碼) | 判 RE。每支學生程式都一起編譯一個小檔把 stdout 設成不暫存，所以當掉前 printf 的內容不會遺失；預設仍比對已印出的內容給部分分數，`runtime_error_zero = 1` 才直接 0 分。`return 1` / `exit(1)` 不算 RE |
| 溢位沒當掉但印出**亂碼** | 當一般 WA：亂碼的每個不合法 byte 各算 1 CHAR 差異，NUL 顯示成 ␀ |
| **無限輸出** | 每 20 ms 檢查輸出檔大小，超過 10 MB (`output_limit_mb`) 用 Job Object 結束 → OLE，該題 0 分。20 ms 內可能多寫幾 MB，(修正後) 這種輸出只讀前 64 KB 進記憶體給畫面用 |
| **無窮迴圈** | 60 秒 (`timeout_ms`) → TLE，0 分；時間限制 < 10 秒時第一次超時會重跑一次確認 |
| **記憶體爆掉** | Job Object 每個 process 512 MB 上限，超過時配置失敗通常會當掉 → RE |
| 整數溢位、算錯 | 只是 WA |
| 輸出超長但在上限內 | 差異數照算 (見第 3 節第 2 項)；畫面與報告只顯示前 64 KB，差異標示只在 n×m ≤ 300 萬格時做 |
| 參考答案本身溢位 | 沒有 .out 的測資會直接停止批改並提示；有 .out 的以 .out 為準並在驗證報告中警告 |

仍要注意：這不是沙盒，學生程式可以讀寫檔案與連網；輸出上限的 20 ms 檢查有些許超出；`_IONBF` 讓每次 printf 都是一次系統呼叫，輸出極大的程式會比在終端機慢。

## 4. 新功能：編譯失敗 → 本機 AI 最小修正 → 雙重扣分

- 設定 (`grader.cfg`)：`ai_fix`、`ai_fix_tool`、`ai_fix_penalty_per_char`、`ai_fix_penalty_max`、`ai_fix_attempts`、`ai_fix_timeout_ms`；畫面上的「編譯失敗與執行異常的處理」群組；CLI `--no-ai-fix`、`--ai-tool`。
- 流程：`grader.c try_ai_fix` → `ai_fix.c` (找工具、`cmd /c <tool> < prompt > answer`、去 Markdown 圍欄) → 再編譯 → `fix_chars = 編輯距離(原始碼, 修正後)` → 執行測資 → 成績 = max(0, Σ各題得分 − 修正扣分)。
- 呈現：表格狀態「CE→AI 修正」(淡藍)；詳細視窗「查看 AI 修正」；HTML 報告新增「編譯錯誤的 AI 自動修正」區塊 (原始碼紅字 = 被改掉、修正後綠字 = 新增，沿用輸出比對的標示器)；CSV 新增 `FixChars`、`FixPenalty` 欄；`CompileStatus = CE Fixed`。
- 失敗處理：找不到工具 / 超時 / 回答非程式碼 / 修 N 次仍失敗 → 維持 Compile Error 0 分，`note` 寫原因，報告附最後一次嘗試。
- 驗證：單元測試 (`ai_extract_code`、提示詞、`config_fix_penalty`、透過 cmd 走一趟 stdin→stdout)；端對端用假工具 (`ai_fix_tool = cmd /c type 修好的.c`) 批改 `004_compile_error` → `CE Fixed`、修正 1 字元、成績 = 三題得分 40 − 1 = 39；真實 claude CLI 呼叫管線通了 (有回答、失敗時降級為 CE)，但這台電腦的 claude 2.1.218 太舊，需要 `claude update`。

## 7. 深色科技風主題 (追加)

整個桌面程式改為深色主題，全部以 Win32 自繪完成，不加外部函式庫 (`src/gui_common.c` 的 `gui_theme_*`)：
- 調色盤集中在 `g_theme` (深藍黑底、青色強調、狀態色)；視窗底色由視窗類別筆刷提供。
- 按鈕 / 核取方塊 / 選項按鈕用 `NM_CUSTOMDRAW` 自己畫 (保留 Windows 的自動勾選與焦點邏輯)；主要按鈕 (`gui_mark_primary`) 用強調色。
- 群組框不用控制項 (Windows 群組框不接受 `CDRF_SKIPDEFAULT`)，改在主視窗 `WM_PAINT` 畫圓角面板與標題 (`gui_draw_panel`)。
- 表格：深色底、交錯列、狀態列色 (全對綠 / 失敗紅 / AI 修正藍 / 異常黃)；表頭以 `SetWindowSubclass` 自繪並畫排序箭頭；`DarkMode_Explorer` 主題讓捲軸變深色 (Windows 10 1809+，舊版自動忽略)。
- 輸入框去掉 3D 凹框改細框線、下拉選單套 `DarkMode_CFD`、進度條與狀態列自訂顏色 (狀態列文字用 `SBT_OWNERDRAW`)、標題列用 `DwmSetWindowAttribute` 深色。
- 所有對話框 (詳細、評分規則、測資、文字視窗、貼上名單) 共用同一組訊息處理：`gui_theme_ctlcolor` / `gui_theme_notify` / `gui_theme_drawitem` / `gui_theme_window`。
- 系統 MessageBox 與檔案選擇對話框維持 Windows 預設外觀 (無法自訂)。
